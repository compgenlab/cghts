# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`cghts` is a pure-Go library for computational genomics file formats: native
readers and writers for FASTA/FASTQ, SAM/BAM/CRAM, BGZF/tabix, BED, GTF, VCF, and
bigWig/bigBed, plus sequence alignment and analysis utilities. No cgo; the only
third-party dependency is `ulikunitz/xz`. It is the library half of the former
`cgkit` project.

The CLIs that consume it live in separate repos: `cgkit`
(`github.com/compgenlab/cgkit`), the general-purpose genomics CLI, and `nupa`
(`github.com/compgenlab/nupa`, private), a focused Oxford Nanopore UMI and poly(A)
toolkit. The ONT-specific commands (`trim`, `umi-cluster`, `umi-dedup`,
`polya-site`) live in nupa, so this library stays domain-general — any
Nanopore-specific handling here (e.g. the aligner's homopolymer discounts) is a
reusable feature, not the library's focus.

**Module:** `github.com/compgenlab/cghts`
**Go version:** 1.24 (raised from 1.23 by `parquet-go`, which `gtstore/` requires)

## Commands

```bash
# Run all tests
make test
# equivalent to:
GOCACHE=/tmp/go-build-cache go test ./...

# Run a single test
go test ./align/... -run TestCigarCondense
```

When developing alongside `cgkit` and `nupa`, the modules are joined by a
`go.work` workspace in the parent directory so those CLIs resolve this checkout
directly. This Makefile exports `GOWORK=off`, so the library always builds
standalone regardless of the ambient workspace.

## Architecture

### Package Layout

- **`seqio/`** — FASTA/FASTQ readers with gzip support. Core type is `SeqQual`, which holds sequence, quality scores, name, and strand. Readers are streaming via `NextSeq()`.
- **`align/`** — Smith-Waterman local alignment with affine gap penalties. Includes special handling for Oxford Nanopore homopolymer error profiles, plus MSA via incremental consensus.
- **`htsio/`** — SAM/BAM/CRAM reading and writing. Native BAM and SAM readers/writers; samtools only for CRAM. Includes BAI/TBI/CSI index parsers, tabix reader/writer, sorted BAM writer with merge sort. Subpackages: `bam`, `bgzf`, `cram`, `codec`, `sam`, `tabix`, `bbi`.
  The tabix index records its **preset** in the header `format` field, and the VCF preset derives each record's end **from the record** rather than from a column: `col_end = 0` is not a claim that VCF records are one base wide, which is a separate spec rule applying when `col_beg == col_end`. Writer and reader must both apply it -- the reader's end feeds the overlap test, so an understated record is dropped even when the index pointed straight at it. Before this the preset was hardcoded to 0, so every VCF `.tbi` written here declared itself generic and nothing could apply VCF rules on read; indexes written earlier still read that way, so a gVCF or SV VCF must be re-indexed to benefit.
  **Each reference's record count is in the index**, in the SAM spec's optional *pseudo-bin* (bin 37450 in BAI/TBI, `((1<<3(depth+1))-1)/7+1` in CSI; chunk 1 is the reference's first-record/last-record extent, chunk 2 is `(n_mapped, n_unmapped)` -- counts, not offsets), plus a trailing `n_no_coor`. htslib writes it for every index, any preset; cghts writes it since v0.12.9, identically (`TestRecordCountsAgreeWithHtslib`), so `bcftools index -n` reads a cghts VCF index. Readers parse it into `RefStats` (`BinIndex`/`CSIIndex.RefStats`, `Reader.RecordCounts`) and never keep it as a bin. An index without one -- older cghts -- reports the count as *unknown*, not zero. **Query ends are clamped** to what the scheme covers (2^29 for TBI/BAI), as htslib's `hts_reg2bins` does: whole-contig queries pass `math.MaxInt32`, and unclamped each level's bin loop ran on into the next level's numbers and the pseudo-bin (150k bins, 98k bogus), which only failed to return its counts as a byte range because tabix's `n_unmapped` is always 0.
- **`htsio/bgzf/`** — BGZF (Blocked GNU Zip Format) reader, writer, and indexed reader with LRU block cache. Used by BAM and tabix layers.
- **`htsio/bbi/`** — Random-access reader for UCSC BBI files (bigWig/bigBed); self-indexed, standard-library only. Reader surface mirrors `htsio/tabix`.
- **`bed/`** — Streaming and tabix-indexed BED readers plus a writer. Core type `BedRecord` (0-based half-open, BED6 fields + verbatim `Extras`).
- **`gtf/`** — GTF gene-model parsing (genes → transcripts → exons/CDS) with an interval index and genic-region classification; a port of ngsutilsj's `GTFAnnotationSource`. `AnnotationSource` (in-memory) and `IndexedAnnotationSource` (tabix-backed).
- **`vcf/`** — Streaming and tabix-indexed VCF reader/writer with a lazy record model (`VcfRecord` parses columns on first access; `Pos` is 1-based). Subpackages: `vcf/annotate` (composable INFO/FORMAT annotators + `Pipeline`) and `vcf/filter` (composable FILTER-stamping filters).
  `RefSpan`/`RefSpanEnd` give a record's reference extent -- the widest of `len(REF)`, `INFO/END`, `INFO/SVLEN` for symbolic alternates measured on the reference, and `FORMAT/LEN` for reference blocks -- and `IsRefBlock`/`IsRefBlockAlt` tell a gVCF block from a variant. Do **not** reach for `AltPositions` for this: it resolves an SV's *partner breakpoint*, which may be on another chromosome and may precede POS, and using it as an extent gave `vcf-tobed` a one-base overhang on every deletion. The rules live once in `internal/vcfspan`, shared with `htsio/tabix` (which cannot import `vcf`, since `vcf` imports it) so an index and a reader cannot disagree about how far a record reaches. `IsRefBlock` means *no* alternate is real, because GATK writes the block allele beside a genuine one as `G,<NON_REF>` and treating its presence as sufficient drops every real call in a gVCF. `BlockDepth` reads `FORMAT/MIN_DP` (falling back to `DP`, which is a **weaker** claim -- the depth at POS, not across the block) and `BlockRGQ` reads `RGQ`, which GATK writes in place of `GQ` on a block. Absent, empty and `.` are all unknown, never zero: a zero depth is a real claim and unknown depth is not, and conflating them makes a gate admit everything.
- **`iosource/`** — Pluggable random-access byte sources behind a concurrency-safe `io.ReaderAt`: local-file and HTTP(S)-Range implementations, plus sibling-index resolution. Lets index-driven readers fetch byte ranges from remote files. Wired into `htsio/tabix` (`NewReaderFromSource`), `htsio/bbi` (`NewReaderFromSource`) and `gtstore` (`OpenParquetContext`); use `iosource.ReadSeeker` to adapt a `ByteSource` for BGZF. `iosource.Open(ctx, locator)` dispatches on scheme; **`iosource/s3`** registers `s3://` for reading (blank import) and **`gtstore/sinks3`** registers it for *writing* a store (see `gtstore.Sink`). Those two are the reason cghts depends on the AWS SDK; both are separate packages so a program that never touches S3 does not link it.
- **`gtstore/`** — Sparse alt-only genotype store in Parquet plus a VCF-backed store behind the same `Store` interface.
  **The name is part of the format.** It was `varstore` until the rename that also moved the archive marker (`varstore.json.gz` → `gtstore.json.gz`) and the Parquet metadata keys (`cgkit.*` → `gtstore.*`). `StoreManifestVersion`, `VolumeManifestVersion` and `FragmentFormatVersion` went to 2 with it, and anything older is refused with `ErrLegacyStore` ("reconvert") rather than read: there is no compatibility reader, because the old keys would otherwise read as absent metadata, which is a wrong answer and not an error. A leftover `varstore.json.gz` is recognised (`LegacyStoreMarker`) only to name the problem; `StoreKind` probes for it last, so a VCF or current store never pays for the check.
  **Three words, three levels, all split by coordinate** (store → volume → shard): a **store** (`GTStore`, `OpenStore`) is an archive of **volumes**, disjoint by chromosome, marked by `gtstore.json.gz` (`StoreManifest`: the sample roster and `ManifestParams` every volume must share, plus the volume list); a **volume** (`ParquetVolume`, `OpenParquetContext`) is one complete store, normally one chromosome, marked by `manifest.json.gz` (`VolumeManifest`); a **shard** is a coordinate range inside a volume, written when `WriterOpts.ShardSites > 0` as `calls/00007.parquet` etc. with its bounds indexed in the volume manifest (`TableInfo.Shards`), so a locus query picks its file from the manifest instead of fetching a large footer. The **tables** (calls/catalog/catalog_runs, optional ref_blocks) split by *data kind*, a different axis: every shard has all of them, cut on the same site boundaries, and a shard never spans chromosomes. Volumes open lazily and are checked against the archive's agreement as they open; `BuildStore` writes the archive manifest over existing volumes and refuses ones that disagree on samples (order included), `MinDP`, `DepthBands` or a shared chromosome. A bare volume opens as an archive of one, so callers do not branch. Archive markers are a *separate file* rather than a `kind` field in `manifest.json.gz`, so an older reader says "not a volume" instead of misreading one.
  **Optional data in a volume**: `ref_blocks.parquet` (`RefBlock`: per-sample spans with `MinDP`, a positive claim about **every** base it covers; absent means "nobody said", not "covered nowhere", and `Params.RefBlocks` is what is believed rather than probing for the file -- `Classify`, `ClassifyMany` and `Calls(IncludeRef)` read it **off the catalog only**, and `Calls` only for exact loci the query names, never by enumerating a span; shards are pruned by chromosome alone, because catalog-run shard bounds are site ranges and a block answers precisely between sites; `WriteRefBlock` refuses a sample off the roster. Blocks come from per-sample **fragments** (`fragment.go`: `NewFragmentWriter`/`ReadFragmentMeta`/`FragmentBlocks` -- one Parquet file per chromosome plus `fragment.json`, written last as the completion marker, cleared first on a rerun), coarsened by `Coarsener` (`coarsen.go`): merge **abutting** blocks within a depth band, drop blocks below the gate, and **never merge across a gap or a `Barrier`**. A gap is bases the gVCF put below the gate or never reported, so a block bridging one answered `0/0` where nothing was assayed; the old `MaxGap` tolerance (10 bp, chosen for an 8.4x row saving at 0.35% of bases over-claimed) was withdrawn for that reason. `ManifestParams.MaxGap`/`FragmentMeta.MaxGap` survive only to recognise data from that era: `NewFragmentWriter` refuses non-zero, attach refuses such a fragment and refuses to `--replace` into such a table (a `--rebuild` clears it). Barriers are a variant record or a no-call block, the gap that keeps coverage from claiming reference where the sample carries something. `AttachRefBlocks` (`attach.go`) merges fragments into a volume as **one k-way merge** sorted on (start, sample), batched as a tree so 10k fragments never hold 10k files open, whose inputs are fragments plus -- when *replacing* samples -- the existing table with those samples filtered out; a *rebuild* reads fragments alone, and attaching over existing blocks without saying which is `ErrRefBlocksExist`. Output goes to a **new generation of files** split at the catalog's shard starts (ref_blocks shard bounds are block extents, a partition of the chromosome), and the manifest, rewritten last, is the switch -- so the volume reads as before until it lands, and a replace can read the table it replaces. Every volume gets a table, even an empty one: present-but-empty says "checked, nobody covered", and an archive needs every volume to agree on `RefBlocks`. Attach also records **whose fragments were merged** (`VolumeManifest.RefBlockSamples`, roster order; `ParquetVolume`/`GTStore.RefBlockSamples()`), which is the only way to tell a sample whose gVCF reported nothing at a position from one whose gVCF was never attached -- the table holds only samples with a block, and a summary must not scan it. A pointer, so nil (unknown: no blocks, or attached before the field) differs from an empty list; a `--replace` over an unrecorded table stays unknown rather than claiming everyone else was removed. `BuildStore` hoists the list to the archive when every volume agrees and otherwise leaves each `VolumeInfo` its own, so a disagreement stays visible. **Every chromosome a fragment has blocks on is answerable**, via `AttachRefBlocksToStore`: a store routes by chromosome to the volume whose census holds it, and a chromosome with no catalog site (chrM, unplaced contigs, chrY in an all-female cohort) used to have none, so its blocks were unreachable. On an archive each such chromosome gets a **blocks-only volume** (the first volume's samples and settings, empty catalog, its blocks) registered by rewriting the archive manifest last; on a single volume the volume takes it (`AttachOpts.ExtraChroms`). A chromosome joins a census only if it gained a block -- putting every declared contig in every volume would give a locus as many answers as volumes); captured **INFO** fields as typed `info_*` columns on the catalog (`WriteSiteInfo`, keeping the source key so `info_r2` and `info_dr2` stay distinct estimators); captured **FORMAT** fields as `fmt_*` columns on calls (`WriteCallFormat`, off by default because calls is ~100x the rows of the catalog). Both take Number `1` and `A`, and `.` as **verbatim text** whatever the declared Type -- `InfoFieldFor`/`FormatFieldFor` do the coercion and `Validate*` refuses a non-String Number=. -- because a variable-length value has no per-ALT split to trust and a numeric column would keep only the rows that happen to carry one value; it repeats down a multiallelic record's rows like Number=1, and the manifest's String/`.` says the column is raw text. The manifest's `Params.Info`/`Params.Format` are the only way to tell an absent capture from a zero. Callable runs carry `min_dp` and are broken at `DepthBands`, so a reconstructed `0/0` has a depth bound rather than only "passed the gate".
  **Queries filter and show captured INFO/FORMAT** (`annot.go`). `Query.ExcludeInfo`/`RequireInfo` filter sites on an INFO field's **presence** (a Flag set, or any value; Number=A per allele), and an excluded site is treated as **off the catalog**: no ALT calls, no reconstructed `0/0` -- but at an exact locus the query names, `ref_blocks` may still answer, except for a sample the store has as a carrier at that record (store and gVCF would disagree). `Query.WithInfo`/`WithFormat` (`"*"` = all) attach rendered values as `Call.Extra` (`*CallExtra`, a pointer so `Call` stays comparable and costs nothing unasked). Both backends read values the way conversion captures them -- `InfoValue`/`FormatValue` are that reading, for the converter to share -- and render through `ValueText` (shortest round-trip float, so VCF `0.870` and stored 0.87 both say `0.87`). A field the source lacks is `ErrNotCaptured`, never "absent" (a filter on an unrecorded field would keep or drop everything); a volume with an empty catalog (blocks-only) is exempt. On a VCF every header field is available, and `*` for FORMAT excludes GT/DP/GQ/AD, which are already columns. A reconstructed `0/0` carries site INFO but no FORMAT, the same asymmetry DP/AD/GQ have. Every reference call says what it rests on, in `Call.RefSource` (`RefFromCatalog` for a run or a VCF record, `RefFromBlock` for a block), set by the backend that emitted it -- a caller cannot recover this, since an excluded site is in the catalog yet answered from blocks. `Classify`/`ClassifyMany` do not take the filter. `Query.IgnoreRefBlocks` answers as though no blocks were attached -- the store's `ref_blocks` is not read (`offCatalogRefs` returns early) and a gVCF's block records are skipped -- so one store can be benchmarked with and without them; catalog answers are unchanged. `ParseTargetsWith(…, TargetOptions{Passing})` drops FILTERed records from VCF target files (`Targets.Filtered` counts them).
  **Reading a record allocates nothing per genotype** (`SampleReader`, `forEachAllele`): `vcf.Sample` builds a map of every FORMAT key per sample, and conversion needs four, so on a 30,000-sample imputed cohort the converter spent ~60% of its CPU in the garbage collector and most of the rest building those maps and splitting GT strings. `NewSampleReader` resolves GT/DP/GQ/AD once per record and reads each through `VcfRecord.SampleField` (a substring of the line; a sample already parsed through `Sample` is read from that copy, so edits are seen), and the GT predicates walk alleles in place; `CallFor` decides carrier status before building the recoded GT. `gtparse_test.go` holds the old Split-based readers and requires agreement. Measured 2.5x wall on a synthetic 30k-sample mixed typed/imputed chromosome, store bytes unchanged.
  **Buffered rows own their strings** (`detach.go`): the Writer batches 8,192 rows per table before parquet-go copies them, and the VCF reader's CHROM/REF/ALT/FORMAT values are substrings of the record line -- megabytes in a wide cohort -- so a buffered row used to pin its whole line, and memory grew with cohort width x batch size (a 10k-sample convert peaked at 1.2 GB, 54 MB after; a wider one was OOM-killed at 8 GB). Every buffered string is cloned, chromosome and sample interned; `TestBufferedRowsDoNotPinTheirSource` checks the pointers. **Writing goes through a `Sink`** (`OpenSink`, `CanWrite`), local or registered by scheme; the sink owns removal as well as creation because aborting differs by transport (unlink a local file, abandon a multipart upload).
  `Open(ctx, locator, kind)`/`StoreKind` own backend resolution (the archive marker `gtstore.json.gz` first, then a VCF suffix, else a volume manifest found at the locator) so the CLI does not re-derive it; `StoreKind` reports an unregistered scheme as a *transport* problem rather than an unrecognized format, since the fix is importing a package, not checking the path. `VcfStore` holds its ctx (`scan` opens lazily on every call and the interface has no ctx-taking method), probes for a tabix index **once at open** rather than per locus — `SiteKnown` runs once per queried variant, so remotely the old per-locus `os.Stat(path+".tbi")` was one index re-fetch per lookup, and could not work for a URL at all — and exposes `Indexed()` so a caller can warn that an unindexed remote VCF streams the whole object per query. `Sites(fn)` is on the interface and implemented by both: for Parquet it reads the catalog, for a VCF it is a full pass computing AC/AN/NCarriers on the way, leaving `NCalled`/`NLowDP` zero because both are defined against a `--min-dp` a plain VCF has no record of. **A store is a directory** holding `calls.parquet`/`catalog.parquet`/`catalog_runs.parquet`; `cohort`, `cohort/` and `cohort/calls.parquet` are all accepted and `TrimStoreSuffix` normalizes them without touching the filesystem (it cannot, for a remote locator). The former filename-prefix form (`cohort.calls.parquet`) is gone: keeping both meant every path decision first had to guess which was meant, and `TablePath` uses `joinStore` rather than `filepath.Join` because Join would clean `s3://bucket/x` into `s3:/bucket/x`. `NewWriter` creates the directory itself, since creating a store *is* creating its directory.
  **Opening a store reads footers, not row groups** (`openFooter`/`openForScan` in `table.go`). parquet-go's default open eagerly reads the page index and the header of *every row group's bloom filter* -- one random read per row group per filtered column -- and every shard used to be opened that way twice (once to open, once to verify its row count), so `gtstore create` on a 30,000-sample store sat for 15+ minutes at near-zero CPU on cluster storage. Metadata and verification opens now skip both; a scan's open keeps the page index eager (pruning reads a column index per row group, and one contiguous read beats one per group) and loads bloom filters lazily. Measured on a two-volume test store: 12,766 reads to 214. `TestOpeningATableReadsOnlyItsFooter` guards it; do not reintroduce a bare `parquet.OpenFile` on a store table.
  **A store is readable only with its `manifest.json.gz`**, written last by `Writer.Finish` (gzipped JSON, temp+rename, `Sync` before the rename so the marker cannot become visible ahead of what it certifies). `NewWriter` deletes any existing manifest *first*, so a store under construction never carries a completion marker — otherwise a `--force` retry that died would leave the previous run's manifest vouching for this run's half-written members. Open verifies `complete`, refuses a `format_version` from the future, and checks each member's recorded row count against that member's own parquet footer; that last check is the only thing that catches a well-formed member belonging to a *different* conversion, since catalog and catalog_runs carry no metadata of their own. The per-chromosome census is accumulated by the writer in `WriteCall`/`WriteSite` rather than supplied by the caller, so it records rows rather than intent — which matters because `MetaSource`/`MetaContigs` are stamped at construction and a three-chromosome store from a 22-input run names all 22 of both. A member may be absent only if the manifest recorded zero rows in it (the `--no-callable` shape). No escape hatch: an unfinished store answers "not assayed" for everything it never reached, which is indistinguishable from the honest answer.
  **A conversion that cannot finish must not leave something that looks finished.** A parquet footer is written only by the writer's `Close`, so a valid footer means a member was completed — which is why `Discard` unlinks *without* closing the writers (closing them first wrote complete footers into files about to be removed, so a kill mid-`Discard`, or a failed unlink, left a well-formed partial store), `abort` reports the removal error instead of swallowing it, and `Close` stops at the first failure rather than finalizing the rest. Three well-formed members that disagree is the one outcome a reader cannot detect. `catalog`/`catalog_runs` footers are also parsed at open, so a truncated member is an error while a genuinely absent one (`--no-callable`) is not. The point of the interface is that both backends answer identically: a query against a VCF and against a store converted from it must agree, which is what the consuming CLI's cross-backend tests assert. **One method does the querying** — `Calls(Query) (iter.Seq2[Call, error], error)`. `Query` selects sites (`Loci`, `Spans`) on one axis and `Samples` on the other, and an **empty selector means no restriction** on that axis, so the zero `Query` is every genotype in the store. `IncludeRef` additionally emits reference (`0/0`) calls. `CollectCalls` buffers into a slice for callers that do not stream.
  **A query is always one pass, however many selectors it names**; its shape changes only how much of that pass is skipped — the Parquet side prunes row groups against the *union* of the selectors, the VCF side takes a tabix seek when there is exactly one selector and otherwise scans and filters per row. So a caller cannot turn an N-variant panel into N lookups, which is the whole reason the four earlier query methods collapsed into this one: **bulk is flat where a per-locus loop is linear** (~19 ms vs 6.6 s at 1000 targets, 349×, on the machine that ran it). Treat the ratio as the durable claim and the milliseconds as hardware-bound; `cgkit`'s `internal/cmd/vcfcmd/bench_test.go` regenerates the corpus from a seed and re-measures. Do not add a per-locus fast path without re-running it.
  Rules callers must respect: rows arrive in the **store's own order** (contig order as written, *not* lexicographic — sorting `chrom` as a string puts `chr10` before `chr2` and yields an unindexable VCF); `Missing == -1` (columns are required, absence is in-band, so test before use); the catalog decides which table answers (a locus absent from `catalog.parquet` is unassayed for *every* sample unless the volume carries `ref_blocks`, and catalog runs are never consulted off the catalog; at a catalog site `ref_blocks` is never consulted, since "in the catalog with no run" is a genotype the caller declined and a block must not overrule it — `SampleState.RefSource` says which source a reference rests on); and `CanonKey`/`SameChrom` (stores keep the source's own contig spelling, so `chr17`/`17`/`NC_000017.11` must be compared canonically). A reference call is emitted only where the genotype was **all**-reference: at a multiallelic record a 0/2 sample carries a different alternate, so writing `0/0` for it would fabricate a genotype — the exclusion is keyed on the source *record* (`Locus.Record()`), not the split locus. `Calls` with `IncludeRef` and `Classify` both return `ErrNotClassifiable` rather than degrade when the store lacks the evidence (no `catalog`/`catalog_runs`, or built `--no-callable`).
  One asymmetry the interface does *not* hide: the backends promise identical **answers**, not identical memory. `IncludeRef` on the Parquet side has to interleave rows derived from three files in one order, so it materializes before it yields — bounded by the query, not by the store, which is fine for a panel or a named sample but means an *unrestricted* `IncludeRef` query holds the whole dense matrix. (The VCF side streams, since a record already carries every sample.) A streaming merge of the catalog and calls scans is the fix if that case becomes real. **A span selects by overlap** (`Span.Overlaps`), not by start position: a record reaching into a region from before it must match, or a region query silently loses every long deletion, SV and gVCF block. The extent lives in the `ref_end` column on `Call` and `Site`; the `Writer` derives it from `len(REF)` when a caller leaves it zero, so no writer has to opt in and the column is never a field of zeros that would make `HasRefSpans` lie. Two consequences to keep in mind when touching this: `wantsSite` and `wantsRecord` must share one span test, since `wantsSite ⊆ wantsRecord` is a structural invariant and widening only the former fabricates `0/0` for a sample carrying a sibling ALT; and the pruning lower bound cannot come from `pos`, because a matching record may start below a row group's minimum — it comes from `max(ref_end)`, which is unsorted and so bounds only that side, the same asymmetry `spanRunFilter` documents for the catalog_runs table. **`VcfStore` reads gVCF reference blocks as coverage.** A block yields one reference row per sample -- never one per base, however wide -- with `Alt` `.`, `RefEnd` carrying the extent, `DP` left `Missing` because a block measures no single base, and `MinDP` carrying the floor. The recorded genotype survives, so a `./.` block is skipped rather than reported `0/0`. `Classify`/`SiteKnown` treat block coverage as an observation, which an explicit record at the locus outranks. `Call.MinDP` is the tightest lower bound the source vouches for and is tagged `parquet:"-"`: derived per query today, a real column when a blocks store exists. **`Gate.Admits` prefers it over `DP`, and that is load-bearing** -- `Missing` passes every gate by design, so a block-derived call would otherwise be admitted unconditionally, the gate silently doing nothing on exactly the state gVCF makes trustworthy. `HasRefSpans()` reads the schema rather than a metadata key, since the column either exists or it does not where a key could disagree with the data. `MetaContigs`/`ParquetVolume.Contigs()` carry the source's `##contig` lines verbatim, because a store is expected to be exported back to VCF and nothing else in the store records which reference it was called against — lengths especially cannot be recovered from the loci a query happens to touch.
- **`support/sequtils/`** — DNA utilities: IUPAC ambiguity code matching, reverse complement, homopolymer run analysis, 4-bit DNA encoding.
- **`support/stats/`** — 2×2 Fisher exact test, Phred/log2 conversions.

### HTS I/O System

The `htsio/` package provides native SAM/BAM I/O without external dependencies (samtools only for CRAM):

- `SamReader` interface: `Next()`, `Header()`, `Query()`, `Close()`
- `Query()` returns `iter.Seq2[*SamRecord, error]` — uses Go 1.23 range-over-func
- `NewSamReader()` auto-detects: `.bam` → `BamReader`, `.sam`/`.sam.gz` → `SamTextReader`, `.cram` → `SamtoolsSamReader`
- `NewSamWriter()` auto-selects: BAM (sorted/unsorted) → native, CRAM → samtools
- All query coordinates are 0-based half-open
- `ParseRegion()` converts samtools-style strings to 0-based half-open
- `IterReader()` bridges `iter.Seq2` back to `SamReader` for legacy callers
- `TabixReader`/`TabixWriter` handle tabix-indexed text files (BED, VCF, GFF) with TBI or CSI indexes
- `bgzf.IndexedReader` has an LRU block cache shared by BAI and tabix query paths

### Alignment System

The aligner (`align/`) is the most complex component:

- `NewLocalAligner()` — Smith-Waterman with soft clipping (for partial matches)
- `NewGlobalAligner()` — Full-sequence alignment
- `DnaAlignmentDefaults()` — Presets for Illumina short reads
- `OntAlignmentDefaults()` — Presets for Oxford Nanopore (looser gap penalties, homopolymer discounts)
- `AlignBatch()` — Parallel alignment using a semaphore-controlled goroutine pool
- Homopolymer discounts are precalculated and cached for performance

CIGAR strings use standard ops: M (match), I (insertion), D (deletion), S (soft clip). Helper functions `CigarCondense`/`CigarExpand` convert between run-length encoded and per-base forms.

## Note

This library carries **no CLI dependencies** (no cobra/pflag) — CLI concerns belong
in `cgkit` or `nupa`. Keep it that way.

Third-party dependencies are deliberately few, and each one must be a *file-format
or codec* need that the standard library cannot meet:

- `github.com/ulikunitz/xz` — CRAM LZMA.
- `github.com/aws/aws-sdk-go-v2` — `s3://` reads (`iosource/s3`) and writes
  (`gtstore/sinks3`). Kept out of every other package, so only programs that
  blank-import one of those two link it.
- `github.com/parquet-go/parquet-go` — the `gtstore/` Parquet genotype store.
  This is the heaviest dependency here: it pulls ten modules transitively,
  including `google.golang.org/protobuf` and `twpayne/go-geom`, and it is why the
  `go` directive is 1.24. It was added knowingly, because `gtstore` is consumed by
  both `cgkit` and Cohort Studio and its four-state classification semantics must
  not be reimplemented per consumer. Go links only imported packages, so binaries
  that never touch `gtstore` are unaffected in size — the cost is `go.sum` weight
  and supply-chain surface for every consumer.

Do not add anything further without a comparable justification.
